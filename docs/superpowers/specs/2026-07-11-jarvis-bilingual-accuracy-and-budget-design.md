# Jarvis 中英混合转写、云端硬预算与桌面修复设计规格

- 日期：2026-07-11
- 状态：待用户快速确认后进入实施
- 目标平台：Windows 10/11 x64
- 基线：`feature/jarvis-mvp`，提交 `a27dc740`

## 1. 背景与已确认问题

当前 MVP 已能手动开始/停止麦克风监听、本地转写、保存音频片段、生成长期记忆，并具备本地声纹校准入口。但本轮实测确认了三个直接影响可用性的问题：

1. Jarvis 使用无边框 Electron 窗口，但 Jarvis 专属页面没有可拖拽区域，因此用户无法移动窗口。
2. 当前默认使用约 142 MB 的 Whisper `base` 模型，并每 5 秒独立转写一次、每段重新自动判断语言；中文和英文混说时上下文过短，容易产生不相关外语词和幻觉文本。
3. 声纹校准虽然已经存在，但首页没有清楚显示“我”的声纹是否已绑定，重启后也缺少可见的持久状态，用户难以判断功能是否生效。

用户已批准采用“本地实时草稿 + 只对低置信度片段做云端纠错”的混合方案，并要求每月设置 5–10 美元的硬预算上限。

## 2. 本轮范围

### 2.1 包含

- 修复 Jarvis 主窗口拖动，并保留最小化、最大化和关闭按钮。
- 把 Jarvis 的默认本地转写模型升级为多语言 `large-v3-turbo`，同时保留本地模型降级路径。
- 将固定 5 秒孤立转写改为带上下文的中英混合转写流水线。
- 加入低置信度判定、重复文本合并和明显幻觉过滤。
- 可选接入 OpenAI `gpt-4o-transcribe`，只纠正低置信度、有语音的片段。
- 在应用内实现默认 5 美元、最高可设 10 美元的月度硬预算闸门。
- 显示云端纠错开关、已用/剩余预算、预算耗尽和离线降级状态。
- 显示“我的声纹”未绑定/已绑定状态，保留本地重新校准入口。
- 对上述路径补齐单元测试、集成测试和 Windows 硬件验收。

### 2.2 不包含

- 后台隐蔽录音、开机自动录音或绕过任务栏录音提示。
- 系统声音采集；本轮只保留既有接口边界。
- 把声纹校准音频默认上传给任何云服务。
- 自动创建 OpenAI 账户、充值或替用户修改供应商后台设置。
- 与本轮问题无关的全仓库重构或泛化式“顺便修复”。

## 3. 总体方案

```text
麦克风
  |
  v
本地 VAD -> 带上下文的本地 Whisper turbo -> 即时草稿
  |                         |                    |
  |                         |                    +--> UI / 本地数据库
  |                         v
  |                  置信度与异常检测
  |                         |
  |              高置信度 --+-- 低置信度
  |                                  |
  |                         云纠错开关 + 隐私同意
  |                                  |
  |                         月度硬预算闸门
  |                                  |
  +---------------------------> OpenAI 转写纠错
                                     |
                                     v
                           版本化替换文本，保留来源

本地声纹嵌入 ------------------------> “我 / 其他说话人”标签
MiniMax（仅文本） -------------------> 10 分钟主题/待办与最终总结
```

关键原则：录音永远先走本地路径。没有 OpenAI Key、用户未同意上传、网络失败或预算耗尽时，录音与本地转写仍继续工作。

## 4. 桌面窗口修复

Jarvis 页面顶部增加 40–48 px 的独立标题栏：

- 标题栏空白区设置 `-webkit-app-region: drag`。
- 最小化、最大化、关闭按钮设置 `-webkit-app-region: no-drag`。
- 复用现有 `WindowControls` 和现有窄权限 IPC，不新增任意窗口控制接口。
- 导航、录音按钮和其他交互控件不放进拖拽区域，避免点击被吞掉。
- 最大化/还原后仍可拖动；双击拖拽区沿用系统最大化行为（若 Electron 当前窗口配置支持）。

验收：用户能从标题栏空白处拖动窗口，三个窗口按钮仍正常，录音按钮点击不受影响。

## 5. 本地中英混合转写

### 5.1 模型

- Jarvis 新安装默认模型改为 `large-v3-turbo`（约 1.6 GB）。
- 首次使用前显示下载大小、进度、失败原因和重试按钮。
- 下载前检查剩余磁盘空间；不足时明确提示并允许选择 `small` 或继续使用 `base`。
- 只改变 Jarvis 的推荐值，不破坏 OpenWhispr 其他页面已有的模型设置。
- 模型加载失败时按 `turbo -> small -> base` 降级，并在 UI 明确显示当前实际模型，不能静默降级。

### 5.2 分段和上下文

- VAD 继续负责剔除静音；只有含语音的 PCM 进入转写。
- UI 可每约 5 秒得到临时草稿，但数据库只提交稳定片段。
- 稳定片段使用约 12–15 秒的语音上下文，并保留约 2 秒重叠。
- 用时间戳和文本相似度去除重叠部分，避免重复句子。
- 将上一稳定片段末尾和中英混合提示作为 prompt；不强制只选中文或英文。
- 默认温度保持 0，优先确定性输出。

中英混合提示的业务语义为：保留原始语言；中文写中文，英文术语保持英文；不要翻译；结合上一段上下文；不确定处使用 `[听不清]`，不要猜造专有名词。

### 5.3 低置信度与异常判定

任一条件满足即可进入“候选云纠错”队列：

- 本地引擎返回的平均 token 概率低于经测试确定的阈值。
- 短片段出现明显非中文、非英文的孤立词，且与相邻上下文无关。
- 同一句或同一 n-gram 异常重复。
- 片段含大量乱码、标点、空结果或 Whisper 常见非语音标记。
- 用户手动点击“重新识别此段”。

过滤器只标记和降级置信度，不直接删除包含实质信息的原始文本。原始本地草稿始终可追溯。

## 6. 云端纠错

### 6.1 供应商与模型

- 第一版使用 OpenAI Transcription API 的 `gpt-4o-transcribe`。
- API 返回 `usage` token 统计，可用于逐请求记账；请求同时申请 `logprobs`，便于保留云端置信度证据。
- 使用自由文本 prompt 描述中英混合场景，并附少量相邻稳定文本，不指定单一 `language`，避免把 code-switching 强制成一种语言。
- 第一版不使用云端 diarization；时间戳和“我/其他人”标签仍以本地流水线为准，避免云端修订破坏已有身份映射。

OpenAI 官方模型页说明 `gpt-4o-transcribe` 相比原始 Whisper 改进了词错率与语言识别；当前标价为音频输入 2.50 美元/百万 token、文本输出 10 美元/百万 token。接口返回 input/output token 用量，并支持 prompt 与 logprobs：

- https://developers.openai.com/api/docs/models/gpt-4o-transcribe
- https://platform.openai.com/docs/api-reference/audio/createTranscription

### 6.2 上传边界

- 默认关闭云端纠错。
- 用户必须在设置中单独打开开关，并确认“低置信度音频会上传给 OpenAI”。
- 只上传低置信度、含语音的最小必要片段及少量文本上下文；不上传整天音频。
- 不上传声纹校准音频、声纹向量、联系人真实姓名或长期记忆库。
- OpenAI Key 通过现有主进程安全存储 IPC 保存；不得进入 localStorage、SQLite、日志、崩溃报告、测试夹具或 Git。
- 用户此前提供的 MiniMax 订阅 Key 只用于 MiniMax 文本总结，不能替代 OpenAI API Key。

### 6.3 修订模型

本地结果先立即显示，云端结果异步到达后创建修订：

- `source`: `local` 或 `openai_correction`
- `revision`: 从 1 递增
- `original_text`: 仅在修订记录中保留
- `current_text`: 当前展示文本
- `confidence` 与 `confidence_reason`
- `corrected_at`
- 保留原有 `session_id`、时间范围和本地 speaker/person ID

网络或 API 失败只把修订标为失败，不阻塞录音，不清空本地文本。

## 7. 每月 5–10 美元硬预算

### 7.1 产品语义

- 默认月度上限：5.00 美元。
- 用户可在设置中调整，MVP 允许范围：5.00–10.00 美元。
- 月份按 UTC 自然月，与供应商项目预算口径一致。
- 达到上限后立即停止提交新的云纠错请求；本地转写继续。
- 预算不会因为关闭/重启应用而清零。

### 7.2 串行预留闸门

为了避免并发请求同时穿透预算：

1. 云纠错队列一次最多发送一个请求。
2. 每次发送前在 SQLite 事务中读取本月“已结算 + 处理中预留”。
3. 每个 `gpt-4o-transcribe` 请求先预留 0.10 美元。该值高于按当前 16k 输入上下文、2k 最大输出和当前单价计算的单请求理论上限 0.06 美元。
4. 若 `已结算 + 处理中预留 + 0.10 > 月度上限`，拒绝发送并显示“预算已保护”。
5. 响应返回后，用 API `usage.input_tokens` 和 `usage.output_tokens` 按随版本固定的价格快照计算实际费用，释放多余预留。
6. 请求失败时释放预留；若供应商返回 usage，则仍按实际 usage 结算。

这样应用不会按照其内置并显示的价格表跨过用户上限，最末尾可能保留不足 0.10 美元的不可用余额。

### 7.3 数据表

`cloud_budget_settings`

- `provider`
- `monthly_limit_microusd`
- `enabled`
- `updated_at`

`cloud_usage`

- `id`
- `month_utc`
- `provider`
- `model`
- `request_id_hash`（只存哈希）
- `audio_ms`
- `input_tokens`
- `output_tokens`
- `price_version`
- `reserved_microusd`
- `actual_microusd`
- `status`: `reserved | settled | released | unknown`
- `created_at` / `settled_at`

该表不存音频、转写文本或 API Key。

### 7.4 真实边界说明

OpenAI 项目后台的 Monthly budget 是软提醒，超过后请求仍会继续；官方明确说明它不是硬停机。因此本产品的“硬预算”由应用自己的串行预留闸门实现，而供应商后台预算只作为第二层告警。若用户在 Jarvis 之外复用同一 Key，外部消费不在本地账本内，Jarvis 无法替外部请求实施硬上限。建议为 Jarvis 创建独立 Project Key，并在供应商后台再设 10 美元告警。

官方说明：https://help.openai.com/en/articles/9186755-managing-projects-in-the-api-platform

### 7.5 价格变化保护

- 价格表必须带 `price_version`，不能从 UI 任意修改。
- 如果 API 返回无法识别的 usage 结构、价格版本未知或无法确定费用，记录为 `unknown`，暂停后续云请求并要求用户确认/更新应用。
- 不允许在费用未知时按 0 美元继续发送。

## 8. “我的声纹”绑定

- 复用当前本地 30 秒校准流程：采集三段有效语音，生成嵌入并合并为“我”的本地 profile。
- 首页和设置页显示 `未绑定 / 校准中 / 已绑定 / 需要重录`，并显示最后校准时间，不显示原始向量。
- 应用重启后通过窄权限 IPC 读取 profile 元数据，不能把整张声纹表暴露给 renderer。
- 用户可重新校准；新 profile 原子替换旧 profile，失败时保留旧 profile。
- 校准音频不落盘、不进入 7 天音频目录、不上传云端；只长期保存本地嵌入及必要元数据。
- 云端文本修订不得改变本地 speaker/person ID。

## 9. UI 状态

设置页新增“转写质量与预算”区：

- 当前本地模型、下载/加载状态和降级原因。
- 云端纠错开关、隐私说明、OpenAI Key 输入状态。
- 月度上限（5–10 美元）、本月已用、处理中预留、剩余预算。
- “预算已保护”“未配置 Key”“网络离线”“仅本地模式”等明确状态。
- 声纹绑定状态和“开始/重新校准”。

实时记录中，每个片段可看到：`本地草稿`、`云端纠正中`、`已纠正` 或 `仅本地`。用户可以查看原文并撤销一次云端修订。

## 10. 安全与隐私

- 录音必须由用户手动开始，任务栏和窗口持续显示录音状态。
- 云端上传和录音是两个独立同意项；同意录音不等于同意上传。
- 主进程负责网络请求和预算事务，renderer 不直接持有 Key。
- 日志只记录请求状态、耗时、音频毫秒数和费用，不记录音频内容、完整文本或密钥。
- 继续执行音频 7 天自动删除；修订文本和记忆按现有长期保留策略处理。

## 11. 测试策略

严格采用测试先行：先写失败测试，再实现最小代码。

### 11.1 单元测试

- Jarvis 标题栏包含 drag 区，窗口按钮是 no-drag。
- 12–15 秒稳定窗口、2 秒重叠和去重逻辑。
- 中英混合 prompt 不强制翻译，不锁定单一语言。
- 低置信度、异常外语和重复幻觉判定。
- 预算事务：正常结算、失败释放、月切换、重启持久化、未知 usage 停机。
- 两个并发调用只能有一个获得预留。
- 剩余预算小于 0.10 美元时不得发新请求。
- 云端修订保留本地时间戳和 speaker/person ID。
- 声纹状态 IPC 只返回允许的元数据。

### 11.2 集成测试

- 使用 mock OpenAI server 验证 multipart 音频上传、prompt、usage 解析和费用计算。
- 无 Key、开关关闭、预算耗尽、超时、401、429、500 时均保持本地录音与转写。
- Key、音频、完整文本不出现在日志或预算表。
- 数据库迁移可在现有用户数据库上重复运行。

### 11.3 Windows 硬件验收

1. 拖动、最大化、还原、关闭窗口。
2. 下载/加载 turbo，并验证磁盘不足与降级提示。
3. 连续录制至少 5 分钟自然中英混说，比较原 `base + 5 秒` 与新流水线的明显错误数。
4. 完成 30 秒声纹校准，重启后仍显示“已绑定”，本人和另一位说话人标签可区分。
5. 用测试预算与 mock 价格快速触发上限，确认不再发生网络请求。
6. 配置独立 OpenAI Project Key 后做一次真实低置信度纠错，核对供应商 usage 与本地账本。
7. 运行现有 Jarvis 测试、类型检查、lint、i18n 检查、生产构建和打包安全扫描。

## 12. 完成标准

- Jarvis 窗口可正常拖动，窗口控件与录音交互无回归。
- 默认本地流水线在中英混说样本上不再频繁产生无关第三语言词；与当前基线相比错误数有可见下降。
- 未配置云端时应用完整可用；云端失败不影响本地记录。
- 应用默认 5 美元预算、可调到 10 美元，并通过事务与预留测试证明不会提交越过预算的新请求。
- 声纹绑定状态在首页可见并跨重启持久化。
- 所有密钥、声纹校准音频和完整原始音频均不进入日志、Git 或云端默认请求。
- 全套自动化检查通过，并完成一次 Windows 真机验收。
