# Jarvis 全天运行与资源治理补充设计

日期：2026-07-12
状态：设计已批准，待书面审阅
基础规格：`2026-07-12-jarvis-trusted-personal-agent-foundation-design.md`

## 1. 目的

本设计把 Jarvis 从“录制期间同时运行多个高负载模型”的桌面录音工具，调整为能够长时间稳定监听、可让出系统资源、最终仍保证信息完整性的个人 Agent 运行时。

本设计不改变已经批准的证据优先原则：音频证据先安全落盘，实时结果只是临时预览，最终转写、人物身份、记忆和计划通过可恢复后台任务完成。

全天模式的核心目标是：

- 用户明确开始监听后，Jarvis 可以跨越长时间静音、讲话、GPU繁忙、麦克风中断、系统休眠和日期切换持续工作。
- 录音可靠性高于实时转写；实时转写高于说话人、记忆和总结的及时性。
- 正常情况下在15至30秒内显示临时转写。
- 其他软件需要GPU时，Jarvis主动让路，但不停止安全采集。
- 普通全天模式不为长时间静音持续生成大型音频文件。
- 重要会议模式仍可连续保存完整麦克风和系统声音音轨。
- NVIDIA电脑使用经过验证的CUDA Whisper；失败时使用严格限流CPU或延期处理。

## 2. 当前资源问题

当前 Jarvis 启动录制时会同时执行：

- 强制本地 Whisper 转写。
- `large-v3-turbo` 模型加载和推理。
- 自动使用可用逻辑处理器的75%，当前参考机为12个Whisper线程。
- 约每12秒处理带2秒重叠的实时转写窗口。
- Silero VAD约每32毫秒进行一次推理。
- 活跃讲话期间约每秒提取一次说话人声纹。
- 音频重采样、音量扫描、WAV转换、证据分片和临时说话人PCM同时进行。

参考机为 Ryzen 7 9700X（8核16线程）和 RTX 5070 Ti（约16 GB显存）。当前安装只包含CPU `ggml`后端，用户数据目录中没有CUDA Whisper组件，也没有有效CUDA启用标记。因此Whisper与ONNX说话人处理会竞争接近全部CPU资源。

问题不在麦克风采样本身，而在实时链路把采集、预览、最终识别和人物识别耦合在了一起。

## 3. 范围

### 3.1 包含

- CUDA Whisper固定版本下载、校验、原子安装、真实后端验证和故障隔离。
- GPU、CPU、电源和显存状态驱动的资源治理。
- 采集、临时预览和最终处理三层隔离。
- 15至30秒平衡预览，以及GPU繁忙时的自动降频和暂停。
- 语音触发、2秒前缓冲、3秒后缓冲和静音时间线。
- 重要会议连续录制模式。
- WAV安全提交后无损转换为FLAC。
- 全天磁盘保护、数据目录迁移和七天删除。
- 持久化后台任务的优先级、背压、积压显示和过期前抢救。
- 说话人处理从实时高频推理改为稳定语音段的后台处理。
- 系统休眠、唤醒、应用崩溃、午夜切换和麦克风中断恢复。
- 全天GUI状态、性能遥测、24小时稳定性测试和发布门槛。

### 3.2 不包含

- 未经用户点击开始就自动打开麦克风。
- 把原始音频或声纹上传给MiniMax。
- 通过非语音环境声音自动推断门铃、脚步或其他事件类别。
- 在GPU繁忙时抢占游戏、渲染或视频会议资源。
- 用有损音频作为唯一原始证据。
- 在本阶段重新训练Whisper、VAD或说话人模型。

## 4. 总体架构

系统拆成三条隔离运行通道：

```text
Capture Lane
麦克风/系统声音 → 环形前缓冲 → VAD/连续模式 → WAV安全提交 → FLAC任务
                                  │
                                  ├── Preview Lane
                                  │   最近未覆盖语音 → CUDA Whisper → provisional
                                  │
                                  └── Final Processing Lane
                                      final transcript → speaker → memory → agent output
```

### 4.1 Capture Lane

Capture Lane拥有最高优先级，不进入AI任务队列。它只负责：

- 从设备接收PCM。
- 维护每条音轨的环形前缓冲。
- 运行单线程轻量VAD或重要会议连续模式。
- 完成分片文件头、哈希、文件原子提交和SQLite事务。
- 记录静音抑制、设备中断、系统休眠和其他时间缺口。

Whisper、声纹、MiniMax、FFmpeg/FLAC转换和数据库分析都不能在音频回调中同步执行。

### 4.2 Preview Lane

Preview Lane产生可丢弃的临时结果：

- GPU空闲时每15至30秒生成一次预览。
- 同时最多执行一个重型预览任务。
- 等待中的旧预览可以被覆盖范围更大的新预览替换。
- GPU忙时预览窗口扩大到45至90秒，必要时暂停。
- GPU恢复后从最新未覆盖位置继续，不追赶所有已经过时的小窗口。
- 结果标记为`provisional`，不能直接生成长期记忆或确认长期人物身份。

### 4.3 Final Processing Lane

Final Processing Lane负责最终一致性：

- 每个已提交音频分片拥有不可丢弃的最终任务。
- 最终转写从WAV或FLAC读取，不依赖预览成功。
- 转写完成后运行说话人分离和长期身份匹配。
- 身份稳定后再运行主题、记忆、Todo、会话总结和每日回顾。
- GPU繁忙、断网、应用重启或系统休眠只会延期任务，不会删除任务。

## 5. 资源治理器

新增独立`ResourceGovernor`，它不执行模型，只提供可测试的调度判定。

### 5.1 状态

- `available`：允许预览和最终重型任务。
- `busy`：检测到其他软件持续使用GPU；采集继续，重型任务延期。
- `constrained`：显存、电源、CPU或磁盘条件不足。
- `unavailable`：CUDA未安装、未验证、版本已隔离或驱动不兼容。

### 5.2 调度原则

- 每个重型任务开始前检查资源状态。
- 已开始的Whisper任务允许完成，不在模型执行中途强杀。
- 同时只运行一个Whisper、说话人或其他重型GPU任务。
- GPU忙不立即触发CPU转写，而是优先延期。
- GPU恢复后按持久化优先级领取任务。
- 使用电池并进入系统节电模式时，只保留采集、证据提交和必要压缩。
- GPU受限超过一分钟时停止Whisper Server并释放显存。
- 重新可用后允许冷启动，接受一次额外预览延迟。

### 5.3 显存判定

CUDA自检记录模型的峰值显存。任务启动前要求：

```text
可用显存 >= 已测峰值 + 安全余量
```

安全余量用于驱动、桌面合成和短期波动。显存不足时任务延期；不能先启动再依赖OOM回退。

### 5.4 CPU回退

- CPU Whisper最多使用4线程。
- CPU进程使用低优先级。
- CPU预览频率放宽到60至90秒。
- 最终任务可以等待CUDA恢复，不要求CPU立即清空积压。
- CUDA不可用且用户仍要求预览时才使用CPU预览。
- CUDA OOM、进程崩溃或驱动重置后，当前任务重新进入队列。

## 6. CUDA Whisper交付

### 6.1 首次体验

- 启动后检测NVIDIA GPU、GPU UUID、驱动和显存。
- 支持的设备首次显示一次安装提示。
- 未经用户确认不下载约755 MB的CUDA组件。
- 用户拒绝后不重复打扰，可在设置中主动安装。

### 6.2 固定版本和完整性

第一版固定使用：

- 仓库：`OpenWhispr/whisper.cpp`
- 发布版本：`0.0.7`
- 资源：`whisper-server-win32-x64-cuda.zip`
- 压缩包大小：754,998,658字节
- SHA-256：`cdac6f0afb951b4213943297943a9865ae822a8669d623d1d6eb46a0dc0a38c6`
- 发布页：`https://github.com/OpenWhispr/whisper.cpp/releases/tag/0.0.7`

不能在运行时直接信任不固定的`latest`。升级CUDA组件必须修改受版本控制的构建清单、SHA-256和兼容性测试结果。

### 6.3 原子安装

安装流程：

1. 在目标数据盘检查压缩包、解压体积和安全余量。
2. 下载到安全临时目录。
3. 校验文件长度和SHA-256。
4. 解压到版本化临时目录。
5. 验证Server和伴随DLL均存在。
6. 执行CUDA自检。
7. 原子切换`current`版本指针或配置记录。
8. 保留上一验证版本用于回滚。

任何失败都不能覆盖当前CPU二进制或已验证CUDA版本。

### 6.4 真实CUDA验证

“请求CUDA”不等于“CUDA已验证”。安装后必须：

1. 使用用户选择的GPU UUID启动Server。
2. 检查Server输出明确加载CUDA后端和目标GPU。
3. 使用内置短音频执行一次实际转写。
4. 验证HTTP响应、文本结构和进程健康。
5. 验证NVIDIA侧出现对应进程或显存占用。
6. 保存组件版本、GPU UUID、驱动、模型、验证时间和结果。

六项全部通过才显示`cuda_verified`。失败时显示具体错误并回退，不得静默标记成功。

### 6.5 隔离和回滚

- CUDA启动失败、DLL缺失、哈希错误、OOM和驱动重置使用不同错误代码。
- 同一组件版本连续失败达到阈值后，在本次启动中隔离。
- 隔离期间不重复拉起进程造成崩溃循环。
- 用户可以重试验证、切回上一版本或删除CUDA组件。
- CPU回退仍受4线程和低优先级约束。

## 7. 语音触发与重要会议

### 7.1 全天语音触发模式

麦克风和系统音轨分别维护VAD状态和时间线：

- 环形缓冲保留最近2秒PCM。
- VAD首次确认语音时，把前2秒一起提交。
- 语音结束后继续保存3秒。
- 间隔不超过3秒的语音合并为同一连续段。
- 底层文件分片最长60秒；长讲话无缝滚动分片。
- VAD使用单线程并与声纹模型解耦。

被抑制的静音保存数据库记录：

- 音轨。
- 开始和结束时间。
- `silence_suppressed`原因。
- 平均音量和峰值音量。

时间线保持连续，但静音范围没有音频文件。

### 7.2 VAD失败

VAD失败不能静默漏录。处理顺序：

1. 立即显示VAD错误。
2. 临时切换到连续保存。
3. 后台尝试重新加载VAD。
4. 恢复后重新进入语音触发模式。
5. 如果磁盘同时达到危险线，安全关闭当前分片并停止新音频。

### 7.3 重要会议模式

- 用户明确切换后，麦克风和系统声音连续保存。
- VAD仍可生成语音索引，但不能裁剪音频。
- 保持独立音轨、60秒分片、哈希、任务和七天策略。
- 退出模式后恢复语音触发。
- GUI和任务栏必须明显区分普通监听与连续会议录制。

## 8. WAV与FLAC生命周期

### 8.1 WAV安全提交

```text
写入 chunk.wav.tmp
→ 完成WAV头
→ fsync
→ 计算PCM SHA-256
→ 重命名 chunk.wav
→ SQLite提交chunk
→ 创建compress_chunk任务
```

SQLite提交完成后才算持久证据。

### 8.2 无损FLAC转换

```text
chunk.wav
→ chunk.flac.tmp
→ 完整解码验证
→ 验证时长/采样率/声道
→ 验证解码PCM SHA-256
→ 重命名 chunk.flac
→ SQLite原子切换活动文件
→ 删除 chunk.wav
```

约束：

- 转换失败保留WAV。
- FLAC验证前禁止删除WAV。
- FLAC解码后的PCM哈希必须与WAV一致。
- 预览、最终转写和播放器通过统一音频读取接口访问，不依赖扩展名。
- 启动恢复会处理残留临时文件、WAV/FLAC双文件和中断任务。
- 磁盘紧张时，压缩任务优先于普通AI任务。

## 9. 存储与保留

### 9.1 未压缩基线

24 kHz、16-bit、单声道PCM的理论体积：

```text
24,000 × 2 字节 = 48,000 字节/秒
约172.8 MB/小时
约4.15 GB/天/音轨
```

连续双轨约8.3 GB/天，七天约58 GB。全天语音触发和FLAC用于把实际增长与讲话时长关联，不能承诺固定压缩比例。

### 9.2 数据目录

- CUDA组件、Whisper模型、临时文件和录音目录支持选择非系统盘。
- 数据目录迁移使用复制、哈希验证、数据库切换、旧目录清理四阶段流程。
- 正在录制时禁止直接移动活动目录。
- UI根据最近24小时实际写入和压缩率显示预计每日用量及剩余可录天数。

### 9.3 磁盘保护

- 可用空间低于卷容量10%或20 GB时进入警告状态，以先达到者为准。
- 可用空间低于卷容量3%或5 GB时进入危险状态，以先达到者为准。
- 危险状态释放约512 MB预留空间，用于完成文件头和数据库事务。
- 完成当前分片后安全停止新音频，不能静默丢帧。
- 压缩、过期清理和即将过期转写在磁盘压力下提高优先级。

### 9.4 七天保留

- WAV或FLAC从音频结束时间计算七天。
- 转写、身份、总结、哈希和时间证据长期保留。
- 删除后保留元数据tombstone。
- 即将到期且未最终转写的分片获得最高后台优先级。
- 到期仍无法处理也必须删除，任务终态为`audio_expired_before_processing`。
- 系统不能因积压暗中延长用户批准的保存期限。

## 10. 后台任务与背压

### 10.1 优先级

持久化任务优先级从高到低：

1. 即将超过保留期但未最终转写的音频。
2. 磁盘紧张时的FLAC压缩。
3. 当前会话临时预览。
4. 普通最终转写。
5. 说话人分离和长期身份。
6. 主题、记忆、Todo、会话总结和每日回顾。

采集不属于该队列。

### 10.2 任务字段

每个任务至少保存：

- 类型和稳定任务键。
- 输入音频、会话和音轨。
- 输入哈希、模型和参数版本。
- 优先级和状态。
- 尝试次数、下次执行时间和错误代码。
- 租约所有者和租约到期时间。
- 实际执行设备：CUDA、CPU或云端。

### 10.3 预览合并

- 最多保留一个等待预览。
- 新预览覆盖旧预览的时间范围时替换旧任务。
- 已执行预览不回写最终证据版本。
- GPU繁忙时不积累小窗口。
- 恢复后从最新未覆盖位置生成较大窗口。

### 10.4 最终任务

- 每个提交分片都有不可丢弃的最终任务。
- 相同音频哈希、模型和参数只处理一次。
- 错误根据网络、资源、模型、音频和永久结构错误分类。
- 重试使用持久化退避时间。
- `completed`、`no_speech`、`blocked`和`audio_expired_before_processing`为可见终态。
- GUI显示待处理音频分钟数和最老任务年龄。

## 11. 说话人处理

移除讲话期间每秒声纹提取。新顺序：

```text
最终音频/转写
→ VAD语音边界
→ 会话内聚类
→ 稳定聚类的少量高质量窗口
→ “我”和长期人物匹配
→ 用户确认与长期样本更新
```

约束：

- 预览只显示临时说话人，不确认长期人物。
- 必须满足批准规格中的最低语音时长和窗口数。
- 自动确认同时满足相似度和差值门槛。
- 用户确认后才能更新长期声音样本。
- Whisper和说话人重型任务不并发。
- 麦克风近讲可以提高“自己”的候选优先级，但仍需质量校验。

## 12. 休眠、崩溃和日期边界

### 12.1 系统休眠

休眠前：

1. 停止接收新音频。
2. 完成当前文件头和数据库提交。
3. 记录`system_suspend`缺口。
4. 停止CUDA Server并释放显存。
5. 保留会话为可恢复状态。

唤醒后：

- 如果应用未退出且休眠前正在监听，自动恢复同一监听运行。
- 恢复期间显示重新连接状态。
- 重新枚举麦克风，继续使用实体设备优先和系统默认回退策略。
- GPU重新检测并通过健康检查后才恢复预览。
- 休眠时段保留为明确缺口。

### 12.2 应用崩溃或完全退出

- 已提交WAV或FLAC为恢复依据。
- 临时文件按头部、长度和数据库状态恢复或删除。
- 过期租约任务重新入队。
- 重启后不静默打开麦克风。
- GUI显示上次监听意外中断，用户点击后继续原会话或开始新会话。
- 正常运行时的短暂麦克风掉线仍无限重试。

### 12.3 午夜切换

- 本地午夜安全关闭当日当前分片。
- 当日会话进入后台处理。
- 在持续明确显示监听状态的情况下创建次日会话。
- 音频、事件和证据按本地发生时间归属。
- 有积压时先生成部分完成回顾，处理完成后生成最终修订。

## 13. GUI与可见状态

任务栏和主界面统一显示：

- `正在监听`
- `正在保存语音`
- `重要会议`
- `GPU预览处理中`
- `GPU忙，已让路`
- `后台处理中`
- `正在恢复麦克风`
- `已暂停`
- `需要处理`

Today页面分别展示：

- 采集状态。
- 临时转写覆盖时间。
- 最终转写覆盖时间。
- 待处理音频分钟数和最老任务年龄。
- CUDA检测、安装、验证、繁忙、回退和隔离状态。
- 磁盘剩余可录时间。
- 当前普通监听或重要会议模式。

不能用单一“正在工作”掩盖阶段差异。

## 14. 安全降级

- CUDA下载或哈希失败：不安装。
- CUDA OOM或驱动重置：任务回队列。
- GPU繁忙：延期，不计为错误。
- VAD失败：临时连续保存并警告。
- FLAC失败：保留WAV。
- Whisper失败：音频保持待处理。
- MiniMax失败：保留本地转写和证据。
- 磁盘危险：完成当前分片后停止新音频。
- SQLite提交失败：文件进入恢复目录，不能显示保存成功。

所有降级都必须保持采集事实、处理状态和用户显示一致。

## 15. 长时间运行优化

- 音量表仅在可见时高频刷新；隐藏窗口降至约1至2 Hz。
- 不可见Electron页面停止无意义动画和轮询。
- 转写片段采用增量写入，不再每次变化同步完整会话。
- 预览上下文使用有界窗口，不复制全天完整转写。
- SQLite WAL检查点、清理和索引维护避开采集路径。
- 日志按大小和日期轮换。
- Whisper、ONNX、FFmpeg和其他子进程登记所有者并在退出时清理。
- 午夜分割会话，避免单个内存对象、列表和事务无限增长。
- 启动时清理孤儿进程、临时文件和过期任务租约。

## 16. 性能与可靠性指标

参考机：Ryzen 7 9700X、RTX 5070 Ti、Windows 11。

- 静音监听10分钟，应用平均CPU不高于约3%，不运行Whisper推理。
- 仅采集和VAD时平均CPU不高于约5%。
- CUDA可用且GPU空闲时，95%的临时转写在30秒内出现。
- CUDA处理期间CPU不能再次长期占用12个逻辑线程。
- CPU回退最多4线程并保持低优先级。
- 检测到外部GPU持续繁忙后，15秒内停止启动新重型任务。
- GPU繁忙期间不丢失已提交音频，最终任务完整保留。
- 普通模式静音时不持续生成音频文件。
- FLAC解码PCM哈希与原WAV一致。
- 24小时运行后内存、进程、文件句柄、日志和任务队列无无界增长。
- 系统休眠、应用强制结束和两次麦克风中断后不丢失已提交分片。

不同硬件保留相同完整性要求；绝对性能基线通过设备能力校准记录，而不是降低数据安全要求。

## 17. 测试

### 17.1 自动测试

- VAD前后缓冲、短静音合并和静音时间线。
- VAD失败后的连续保存降级。
- 重要会议连续单轨和双轨录制。
- WAV提交、崩溃恢复、FLAC转换和PCM哈希一致性。
- CUDA固定版本、SHA校验、空间检查、原子安装和版本回滚。
- CUDA真实后端、GPU UUID和短音频自检。
- GPU忙、显存不足、OOM、驱动失败、版本隔离和CPU限流。
- 预览任务替换、最终任务持久化、租约恢复和过期前优先级。
- 七天删除和`audio_expired_before_processing`终态。
- 说话人任务不再按每秒触发，且不与Whisper并发。
- 午夜切换、系统休眠、应用崩溃和麦克风恢复。
- 数据目录迁移、磁盘警告、紧急预留和安全停止。
- 隐藏窗口刷新降频、增量转写持久化和日志轮换。

### 17.2 人工验收

1. 全天模式连续运行至少24小时。
2. 播放中英混合语音并检查15至30秒预览。
3. 同时运行游戏或GPU压力负载，确认Jarvis让路且继续采集。
4. 断开麦克风两次并恢复。
5. 切换重要会议并验证连续双轨。
6. 强制结束应用并检查证据和任务恢复。
7. 休眠并唤醒，检查同一监听运行恢复及缺口。
8. 重启电脑，确认不未经用户操作自动打开麦克风。
9. 检查最终People、Topics、Todos、Memory和每日回顾。
10. 推进复制测试数据到七天边界并检查音频删除与证据保留。

## 18. 发布门槛

全天模式只有在以下条件全部满足时发布：

- CUDA下载、SHA校验、安装、自检、GPU选择和回退通过。
- 24小时稳定性测试通过。
- 语音触发测试没有吞掉句首和句尾。
- 每个已提交音频都有最终任务或明确终态。
- GPU繁忙不会形成采集缺口。
- FLAC转换保持PCM证据一致。
- 七天策略不会因任务积压暗中延长。
- 磁盘危险状态能安全完成当前分片。
- 任务栏和主界面录音状态始终与真实设备状态一致。
- 完整Jarvis测试、类型检查、lint、i18n、Windows打包和安装后启动验证通过。

## 19. 与现有计划的关系

本设计是基础规格的横切补充，不替代四个实施阶段：

1. 双轨采集与证据层负责引入Capture Lane、VAD时间线、WAV提交、FLAC和磁盘保护。
2. 完整转写与连续会话负责Preview Lane、Final Processing Lane、CUDA Worker、资源治理和背压。
3. 说话人与长期身份负责把实时高频声纹改为后台稳定语音段处理。
4. 证据化记忆与Agent输出遵守最终结果依赖和低优先级调度。

详细实施计划必须把本设计的任务合并进相应阶段，并保留阶段间依赖顺序。
