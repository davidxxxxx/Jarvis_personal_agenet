# Jarvis 启动可靠性、云预算与录音反馈设计

**日期：** 2026-07-17  
**状态：** 已批准，待实施计划  
**范围：** Windows 桌面版 Jarvis

## 1. 背景与已确认问题

本次工作解决五个相互关联、但可独立验收的问题：

1. **应用偶发无法启动。** 两个使用不同 Electron `userData` 目录的进程可以同时访问同一个 `G:\JarvisData\recordings-data`。第二个进程在旧数据接管流程中尝试替换第一个进程正占用的 `jarvis.db`，Windows 因文件锁返回 `EPERM`。
2. **Start Listening 可能长期卡在启动中。** 当前启动顺序会等待模型检查或下载、麦克风授权、媒体流和主进程 IPC，但没有明确阶段、进度或有界超时。数据库可能已经把会话标记为 `recording`，界面却仍显示 `starting`。
3. **MiniMax 预算配置与用户预期不符。** 前端、共享契约、业务层和数据库都把预算硬限制为每月 10 美元，因此 200 美元无法保存；同时没有明确的“不设上限”语义。
4. **录音时缺少输入反馈，主界面过于拥挤。** 已经存在麦克风 RMS 音量数据，但 Today 页面没有清晰的输入波形；右栏长期堆叠日结、MiniMax、转写质量和声纹设置。
5. **Finish and summarize 不在当前窗口显示摘要。** 当前实现只在后台触发最终分析，Today 页面既不等待分析状态，也不读取本次会话的持久摘要。

## 2. 目标

- 同一个外部数据目录在任意时刻只能由一个 Jarvis 实例写入。
- Start Listening 的每一个准备阶段都可见、可超时、可取消、可重试，并且界面状态与持久状态一致。
- MiniMax 支持关闭、设定自定义月上限和明确的不设上限模式；所有模式继续记录用量。
- Listening 区域显示低功耗、可访问的实时输入音量波形。
- 默认 Today 页面只保留当前任务所需信息；低频设置合并进一个抽屉。
- 点击 Finish and summarize 后，当前 Today 页面显示本次摘要，同时把同一份摘要长期保存到 Memory。
- 所有缓存、测试和运行数据继续放在 G 盘，不在 C 盘新增大体积数据。

## 3. 非目标

- 本次不重写转写、说话人分离或长期记忆算法。
- 本次不增加新的音频分析上下文，也不提高现有音频采样频率。
- 本次不把 OpenAI 转写纠错预算改为“不限额”；它继续使用自己现有的独立设置。
- 本次不允许多个实例对同一个数据根目录进行并发写入。
- 本次不删除已有录音、转写、摘要或预算历史。

## 4. 总体方案

### 4.1 启动与数据目录独占

Jarvis 在执行旧数据接管、数据库迁移或打开数据库之前，必须先取得目标数据根目录的独占运行租约。租约使用现有的 `DirectoryLeaseProvider`，并由主进程持有到正常退出完成。

启动顺序：

1. Electron 取得当前 `userData` 范围的单实例锁。
2. 解析最终数据根目录。
3. 取得该数据根目录的独占运行租约。
4. 执行必要的数据接管与迁移。
5. 打开数据库并初始化服务。
6. 应用退出时先关闭录音、数据库和辅助进程，再释放租约。

若租约已被占用，应用不再尝试复制或替换数据库，而是显示可理解的错误：

> Jarvis 已在使用这个数据目录。请先关闭另一个 Jarvis 窗口，再重试。

默认错误不显示 API Key、完整用户目录或内部临时文件名；诊断日志保留错误类别和脱敏后的根目录标识。

旧数据接管还要满足幂等性：

- 源目录与目标目录相同或目标已经完整接管时，直接跳过数据库替换。
- 替换前验证目标是否确实需要更新，避免每次启动重复接管。
- 只清理能够证明属于 Jarvis、未被占用且内容已经成功落盘的陈旧 `.jarvis-relocate-*` 临时文件。
- 失败时保留原正式数据库，不把临时数据库提升为正式数据库。

### 4.2 Start Listening 有界启动状态机

录音启动使用明确的准备状态，而不是单一的 `starting`：

- `checking_model`：检查本地 Whisper/CUDA 能力。
- `downloading_model`：首次安装或下载模型，并显示可用进度。
- `checking_microphone`：重新枚举设备并请求选定麦克风。
- `starting_audio`：启动音频捕获和转写管线。
- `recording`：真实音频流已经开始，界面与持久状态均确认运行。

规则：

- 模型下载允许较长时间，但必须显示下载状态、进度和取消入口，不能表现为无响应。
- 麦克风获取和录音启动使用有界超时。超时先重新枚举设备，再按已有策略避开 Sonar 等虚拟设备并回退到系统默认实体麦克风。
- 任何晚于超时才返回的媒体流都必须立即停止音轨，防止隐形占用麦克风。
- 创建持久会话后若后续启动失败，必须回滚为可解释的失败/已结束状态，不能遗留 `recording` 会话。
- 只有确认媒体流已经工作后，Today 页面和数据库才共同进入 `recording`。
- 初次启动失败显示具体阶段、简短原因和“重试”按钮，不进入无限循环。
- 录音已经成功开始后的音轨中断继续遵守现有策略：重新枚举、避开虚拟设备、回退默认设备，并无限重试；重试期间明确显示“正在恢复输入”，录音会话保持运行。

### 4.3 MiniMax 月预算模式

MiniMax 分析预算改为显式模式，不用超大数字模拟不限额：

| 模式 | 持久值 | 行为 |
|---|---|---|
| 关闭 | `off` | 不发送新的 MiniMax 分析请求 |
| 每月上限 | `capped` | 达到设定金额后停止新的请求 |
| 不设上限 | `unlimited` | 不因金额阈值阻止请求，但持续记录和展示用量 |

`capped` 模式允许 0.01 至 1,000,000 美元，保留小数点后两位。该上界只是数值与误操作保护，不是产品推荐额度；200 美元可以正常保存。界面默认仍推荐 5–10 美元。

`unlimited` 必须显示醒目但不阻塞的说明：

> 不设上限可能产生持续费用。Jarvis 仍会记录估算用量，但不会因金额停止请求。

当云端用量暂时未知时：

- `capped` 模式继续采用保守保护，避免超出用户设定上限。
- `unlimited` 模式显示“用量暂不可用”警告，但不因该原因阻断请求。
- `off` 模式始终阻断请求。

数据迁移：

- 预算策略修订和预算周期都新增明确的 `mode`。
- 现有预算值迁移为 `capped`；现有禁用状态迁移为 `off`。
- 金额继续以 micro-USD 整数保存，所有写入必须是安全整数。
- 策略快照、周期创建、数据库约束、触发器、IPC 输入输出和运行时守卫必须共同认识 `mode`，不能只改前端。
- 所有模式继续保存估算成本、已用金额、周期和最后同步状态。

MiniMax 与 OpenAI 纠错设置合并展示在同一个“云服务”设置区域，但数据、预算和启用状态仍相互独立。

### 4.4 低功耗输入波形

Listening 状态上方新增 `InputLevelWave`：

- 使用已有的 `currentMicLevel` RMS 标量，不创建第二个 `AudioContext`，不增加 FFT，不复制原始音频。
- 显示 24–32 个平滑柱状波纹，柱高由当前音量和固定空间包络共同决定。
- 音频活跃时使用主题色；静音、不可用或正在恢复时变为灰色并显示对应文字。
- 不使用独立动画定时器；仅在已有音量采样更新时改变 CSS 高度。
- 遵守 `prefers-reduced-motion`，关闭非必要过渡动画。
- 提供 `role="meter"`、当前百分比和文本状态，让不能看见波形的用户也能判断输入是否存在。
- 麦克风或双通道模式显示麦克风输入音量；仅系统声音模式若尚无系统音量指标，则明确标注“系统输入音量暂不可视”，不伪造波形。

### 4.5 Today 页面精简与设置合并

默认 Today 页面继续以录音和当前会话为中心：

- 中间区域：输入波形、录音状态、开始/暂停/完成控制、实时转写、完成后的本次摘要。
- 右侧区域：紧凑的“今日/本次回顾”和一行云服务、声纹状态摘要。
- 一个统一的“设置”按钮打开设置抽屉。

设置抽屉分组：

1. **录音输入**：麦克风选择、系统声音和回退策略。
2. **云服务**：MiniMax Key、MiniMax 预算模式和已用金额。
3. **高级**：OpenAI 转写纠错、转写质量诊断、声纹校准。

抽屉关闭后不占用主界面空间。所有原有能力仍可访问，不能因为精简而删除功能。

### 4.6 Finish and summarize 当前页闭环

点击 **Finish and summarize** 后：

1. 立即安全停止并落盘音频，完成转写分片收尾。
2. Today 页面保留本次会话并进入 `summarizing`，显示明确进度，不跳到其他页面。
3. 触发最终分析，并通过持久会话状态查询分析进度。
4. 分析完成后，在当前 Today 页面显示 `SessionSummaryPanel`。
5. 面板读取 Memory 使用的同一份持久摘要，不维护一份只存在于组件内的副本。

面板至少展示：

- 本次概要；
- 主要话题与结论/决定；
- 待办及可识别的负责人、日期；
- Jarvis 建议；
- 说话人和完整转写/Memory 入口。

行为约束：

- 轮询有界且在页面不可见时降频或停止；后台分析本身不被页面卸载取消。
- MiniMax Key 缺失、预算关闭、网络失败或分析结构异常时，当前页显示真实原因，以及“打开云服务设置”“重试总结”“查看已保存转写”等动作。
- 总结失败不能影响已保存音频和转写。
- 用户开始新录音时可以收起上一次内联摘要，但摘要仍保存在 Memory。
- 应用重启后，Today 页面能够恢复最近一次已完成会话及其摘要状态，而不是重新生成或丢失结果。
- 重复点击或重试使用同一会话的幂等最终分析语义，不生成多个相互冲突的摘要。

## 5. 数据与状态一致性

### 5.1 录音

界面状态不能早于真实资源状态：

- `recording` 代表媒体流已经成功启动。
- `recovering` 代表会话仍在运行但当前输入中断。
- `completed` 代表捕获已停止且持久收尾已确认。
- `summarizing` 是分析状态，不等同于仍在录音。
- `ready` 代表本次持久摘要可读。

### 5.2 摘要

Today 与 Memory 通过会话 ID 读取相同的分析记录。任何页面刷新、路由切换或应用重启都不会把摘要降级为仅内存状态。

### 5.3 预算

每个请求在发送前读取当前策略；请求结束后无论模式如何都进行成本核算。策略变更形成新修订，已经发生的用量不被覆盖或清零。

## 6. 隐私与安全

- 麦克风录音状态继续在任务栏/界面中清晰可见。
- 波形只消费音量标量，不持久化额外音频特征。
- API Key 继续通过安全存储处理，日志和错误界面不得输出完整 Key。
- 启动冲突错误不得输出完整数据库路径或内部临时文件名。
- “不设上限”是显式用户选择，不作为默认值，也不能由迁移自动启用。

## 7. 测试策略

实施采用测试驱动，至少覆盖：

### 7.1 启动与迁移

- 两个不同 `userData` 的实例指向同一数据根时，第二个实例在接管前被拒绝。
- 数据根租约在正常退出后释放，下一次启动成功。
- 已完成接管时不会再次替换 `jarvis.db`。
- 陈旧临时文件只在验证安全时清理。
- 租约冲突显示友好错误且不泄露完整路径。

### 7.2 录音启动

- 每个准备阶段正确呈现。
- 麦克风 Promise 永不返回时会超时、清理并回滚持久状态。
- 晚到媒体流会立即停止。
- 选定设备失败后重新枚举并回退默认实体麦克风。
- 首次启动失败可手动重试；成功启动后的掉线继续无限恢复。

### 7.3 预算

- 200 美元可保存、读取并正确换算为 micro-USD。
- `off`、`capped`、`unlimited` 在前端、IPC、仓储和守卫中语义一致。
- `capped` 达限阻断，`unlimited` 达到任意累计金额仍允许请求并记录用量。
- 未知用量在 `capped` 和 `unlimited` 下表现符合设计。
- 旧数据迁移后模式正确，历史用量不丢失。

### 7.4 波形与界面

- 波形使用现有音量值，不新建音频分析器。
- 静音、活跃、恢复和不可用状态可区分。
- reduced-motion 与无障碍 meter 属性正确。
- 主界面不再常驻完整设置卡，所有原功能仍可从抽屉访问。

### 7.5 完成与总结

- 点击 Finish 后当前页面立即显示 `summarizing`。
- 最终分析完成后，当前页面显示与 Memory 相同的持久摘要。
- 分析失败显示可操作错误，不损坏录音或转写。
- 重试幂等，刷新和重启后仍能恢复结果。
- 新录音不会删除上一条摘要。

## 8. 验收标准

- 同一 `G:\JarvisData` 被另一个 Jarvis 占用时，不再出现 `EPERM rename` 启动错误。
- Start Listening 不会无限卡住；用户始终能看到当前准备阶段、超时后的原因和重试入口。
- 输入有声音时，Listening 上方波形有明显但低功耗的响应；静音或断线时状态真实。
- MiniMax 可以保存 200 美元月上限，也可以选择“不设上限”；设置重启后仍生效。
- MiniMax 的不限额不会关闭用量记录，也不会影响 OpenAI 纠错预算。
- Today 页面默认右栏明显精简，低频设置集中在一个抽屉。
- 点击 Finish and summarize 后无需进入 Memory，当前窗口即可看到本次完整摘要。
- 同一摘要在 Memory 中长期可查，退出并重启应用后仍存在。
- 相关单元、集成和 UI 测试通过；打包应用在 Windows 上完成一次真实启动、录音、波形、完成和总结验收。

## 9. 实施拆分

详细实施计划在本规格确认后编写，预计按以下依赖顺序执行：

1. 数据根租约与幂等接管。
2. 预算模式的数据迁移、契约和运行时守卫。
3. 录音启动状态机与超时清理。
4. Today 页面精简、设置抽屉和输入波形。
5. 当前页总结闭环与重启恢复。
6. 回归测试、Windows 打包和真实设备验收。
