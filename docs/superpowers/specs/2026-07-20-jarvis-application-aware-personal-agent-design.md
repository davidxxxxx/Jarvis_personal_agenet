# Jarvis 应用感知个人 Agent 增量设计规格

- 日期：2026-07-20
- 状态：用户已逐项批准
- 目标平台：Windows 10/11 x64 桌面版
- 实施工作区：`G:\Jarvis\.worktrees\jarvis-all-day-runtime`
- 基础规格：
  - `docs/superpowers/specs/2026-07-12-jarvis-trusted-personal-agent-foundation-design.md`
  - `docs/superpowers/specs/2026-07-12-jarvis-all-day-resource-governance-design.md`
  - `docs/superpowers/specs/2026-07-17-jarvis-start-budget-ui-summary-design.md`

## 1. 目标

本增量把 Jarvis 从“能录音、转写和总结”的工具推进为能够理解信息来源、参与关系和行动归属的个人 Agent。

系统不仅要知道“说了什么”，还要尽可能可靠地知道：

- 声音来自实体麦克风、KOOK、Chrome、DOTA 2、会议软件，还是无法归属的混合系统声音。
- `SELF` 是否参与、场景中有多少人、谁在轮流发言。
- 当前活动更可能是工作会议、学习、社交通话、面对面对话、娱乐、游戏或未确定。
- 哪句话只是视频内容，哪句话是本人承诺，哪句话是别人分配且本人接受的任务。
- 哪些结果有资格成为正式 Todo，哪些只能成为待确认事项或候选建议。

所有判断必须建立在可追溯证据、保守置信度和用户可撤销纠错之上。

## 2. 已确认的产品原则

1. 所有检测到的人类语音最终都要完成语音转文字，不因娱乐、游戏或视频类别跳过完整转写。
2. 纯音乐、环境噪声和游戏音效保留为音频活动，不伪造文字。
3. 应用来源、说话人、活动分类和行动归属分别建模，不能用一个推测替代另一个事实。
4. 低置信度保持未知，不能为了“智能感”污染长期记忆、人物或 Todo。
5. 原始音频、声纹向量、真实人物姓名、程序路径和窗口标题绝不上传 MiniMax。
6. 所有声纹向量只在本地加密保存。
7. 工作会议可产生建议；学习建议必须结合学习目标；社交只提取明确约定；娱乐和游戏只记录内容与兴趣，不生成建议或 Todo。
8. 用户仍需手动开始、暂停和结束监听；录音状态始终明确可见。

## 3. 当前实现差距

当前 Windows helper 使用 Process Loopback 的排除模式捕获全部外部系统声音，只得到一条混合系统轨。`audio_tracks` 也只允许 `mic/system`，并通过 `UNIQUE(session_id, source_type)` 限制每个会话只能有一条系统轨。

当前声纹链路已经具备引导录入、会话聚类、人物修订和本地存储基础，但默认 embedding 是英文 VoxCeleb CAM++，还没有落实中文 CAM++ 全天初判、ERes2NetV2 空闲复核和双模型一致性门禁。

当前 `TodayView` 是固定的左侧导航、中间录音/转写、右侧摘要/每日回顾结构。Todo 和 Suggestion 已有持久数据及证据关系，但首页没有按行动优先级展示，也没有严格的归属候选生命周期。

## 4. 应用级音频来源

### 4.1 音频会话发现

Windows 原生 helper 维护活动音频会话列表：

- 使用 `IAudioSessionManager2` 枚举当前音频会话。
- 使用音频会话通知持续维护新增、失效和状态变化，不能只依赖一次枚举。
- 从会话取得 PID，只在内存中完成规范化应用映射。
- 长期只保存 `chrome`、`kook`、`dota2` 等规范化应用键和展示名。
- 原始可执行文件路径、窗口标题和命令行不进入数据库、日志、MiniMax 或长期记忆。
- 同一应用的多个进程按可信进程树和规范化应用键合并，浏览器不区分标签页。

### 4.2 Process Loopback 采集

对进入活动池的应用，使用 `ActivateAudioInterfaceAsync` 和
`AUDIOCLIENT_PROCESS_LOOPBACK_PARAMS` 的 include-process-tree 模式创建独立音轨。

每个会话至少允许：

- 一条实体麦克风轨。
- 一条混合系统安全轨。
- 0–4 条默认应用轨；高级设置允许 1–8 条。

应用轨的原始 PCM、分片、哈希、缺口和最终转写继续使用现有 Evidence Store、`MultiTrackAudioWriter` 和持久任务链。

### 4.3 动态活动音轨池

- 不为所有已打开程序长期创建音轨，只跟踪正在实际发声的应用。
- 应用稳定发声后建立独立音轨；持续静音后释放捕获资源。
- 混合系统轨维护有界前置缓冲，覆盖应用轨建立前的开头。
- 默认最多四条应用轨，优先级为：
  1. KOOK、Teams、Zoom 等通话或会议应用。
  2. 当前前台应用。
  3. 浏览器和学习应用。
  4. 游戏及其他后台媒体。
- 超出上限的声音仍由混合系统轨保留，来源标记为未知。
- 设置页面显示当前活动应用轨、池上限、捕获状态、资源占用和降级原因。

### 4.4 全屏游戏让路

检测到全屏游戏后：

- 安全录音和音量显示继续。
- 应用轨最多保留游戏和一个通话应用。
- 暂停实时转写、声纹、FLAC 压缩、总结及其他重型推理。
- 退出游戏后按照持久任务队列完整补转写和复核。
- 不创建白色悬浮窗口或透明残留窗口。

### 4.5 保守降级

应用重启、设备切换、Windows 拒绝应用捕获或 helper 失败时：

- 自动退回混合系统音频，保证声音不丢失。
- 降级区间标为“系统音频 · 应用未知”。
- 不根据文字内容强行猜测具体应用。
- 恢复后重新建立应用轨，并在时间线记录恢复点和覆盖率。
- 来源未知的内容仍完成转写，但不能生成正式 Todo，不能更新声纹，场景分类最高只能处于“可能是”区间。
- 后续设置可以允许用户选择更严格或更宽松的降级策略，但 MVP 默认始终使用保守降级。

### 4.6 回声和重复

同一声音可能同时出现在应用轨、混合系统轨和麦克风轨：

- 所有原始证据都保留。
- 通过时间、音频相关性和文本相似度确定重复关系。
- 统一转写只保留一份主文本，同时保存其来源关系。
- 低置信度重复不自动合并。
- 回声或重复片段不能成为声纹学习样本。

## 5. 完整转写策略

- 每个包含人声的已提交分片都有不可丢弃的最终转写任务。
- 工作会议、学习、社交和面对面对话优先处理。
- 娱乐视频、球赛、电影和游戏可以等到 GPU 空闲后处理，但必须在保留期内完整补齐。
- 全屏游戏期间不运行实时预览；退出后从已保存证据补齐。
- `no_speech` 必须由 VAD/ASR 明确产生，不能用应用类别代替。
- 应用、说话人和时间戳进入最终转写公共投影。

## 6. 本人声纹和长期人物

### 6.1 本人录入

- 首次录入引导用户完成三段各约 10 秒的本人语音。
- 三段分别保存不可变样本 embedding、模型版本、质量和本地加密密文。
- 录入只允许实体麦克风，关闭自动增益、降噪和回声消除以保持可评测输入。
- 三段内部一致性不足时拒绝录入并要求重试。

### 6.2 双阶段模型

- 中文 CAM++ `iic/speech_campplus_sv_zh-cn_16k-common` 用于全天低成本初判。
- ERes2NetV2 `iic/speech_eres2netv2_sv_zh-cn_16k-common` 用于空闲时、边界样本和高影响身份的复核。
- 两个模型使用各自独立的 embedding 空间、阈值、margin、版本和评测结果，不能混合向量。
- 正式自动关联需要两个模型都通过质量、相似度、margin 和连续窗口门禁。
- GPU/CPU 忙时身份复核延期，不阻塞录音和最终转写。

### 6.3 谨慎持续学习

本人声纹只允许从以下片段增强：

- 来源是实体麦克风。
- 无重叠、非回声、质量达标。
- 高置信匹配本人。
- 用户已经确认。

系统声音、视频人物、重叠说话和来源未知片段永远不能自动更新本人声纹。

### 6.4 其他人物

- 每次会话先生成“说话人 1、说话人 2”等会话级标签。
- 两个模型都高置信一致时，可以关联到跨会话匿名人物“人物 3”。
- 模型可根据自我介绍或上下文显示“可能是张三”，但不能自动保存真实姓名。
- 只有用户确认或手动改名后，才成为长期人物“张三”。
- 不够可靠时保持会话级人物，不强行合并。
- 人物命名、撤销、拆分和合并都有修订历史。

## 7. 活动场景分类

### 7.1 分类集合

第一版固定返回：

- `work_meeting`
- `learning`
- `social_call`
- `in_person_conversation`
- `entertainment`
- `gaming`
- `other`
- `unknown`

显示层使用中文名称，数据库和 IPC 使用稳定枚举。

### 7.2 本地初判

本地分类器按时间段计算特征：

- 规范化应用名。
- 麦克风是否参与。
- 是否检测到 `SELF`。
- 说话人数和轮流发言结构。
- 持续时间和前后台状态。
- 用户允许读取时的日历时间块类别。
- 转写中的低风险主题特征。

本地初判必须可解释、可测试，云端不可用时作为保守结果。

### 7.3 MiniMax 语义复核

MiniMax 按时间段批量接收：

- 规范化应用名，如 Chrome、KOOK、DOTA 2。
- 匿名说话人标签，如 `SELF`、`P1`。
- 相关稳定转写。
- 不包含声音本身的统计信息，如人数、轮流发言和麦克风参与。

MiniMax 返回：

- 类别。
- 置信度。
- 简短判断理由。
- 输入证据引用。

禁止上传：

- 原始音频。
- 声纹或 embedding。
- 真实姓名。
- 程序路径、窗口标题、命令行。
- 未经允许的日历正文。

请求进入现有 MiniMax 预算、持久云队列和共享并发通道。云端失败时使用本地结果；不确定则保持未知且不产生建议。

### 7.4 置信度门禁

- `>= 80%`：自动分类并应用该类别的输出策略。
- `55%–80%`：显示“可能是……”，允许总结，禁止建议和 Todo。
- `< 55%`：归入其他/未确定，只保留记录。
- 来源未知时即使语义很强，也不能超过中间区间。

## 8. 各场景的 Agent 输出

- 工作会议：总结决定、明确承诺、风险和候选建议。
- 学习：记录内容、进度和问题；建议必须与用户确认的学习目标相关。
- 社交通话和面对面对话：记录参与者、主题和明确约定；不推导隐含任务。
- 娱乐视频、球赛和电影：记录观看内容、主题和兴趣，不生成建议或 Todo。
- 游戏：记录游戏、时段、同伴和兴趣，不生成建议或 Todo。
- 未确定：只保留转写、时间线和分类候选。

## 9. Todo 严格归属门禁

只有以下情况有资格成为个人 Todo：

1. `SELF` 明确承诺：“我要做……”“我来处理……”“提醒我……”。
2. 其他说话人明确把任务交给 `SELF`，并且 `SELF` 明确接受。
3. 用户手动把内容转为 Todo。

禁止：

- 视频、直播、播客、课程和游戏解说中的命令式语言生成个人 Todo。
- 分配给其他人的工作任务进入本人 Todo；它们只保留在会议记录。
- 说话人未知、多人重叠或声纹不足时生成 Todo。
- 仅凭主题相似或模型常识推导个人承诺。

## 10. 分级入库

- 用户手动创建：直接成为正式待办。
- `SELF` 明确承诺，且声纹、语义和场景置信度都不低于 90%：自动成为正式待办，标注“自动提取”并支持一键撤销。
- 其他人分配且 `SELF` 接受：先进入“待你确认”。
- AI 推导的建议：只能进入“候选建议”，接受后才能转为待办。
- 没有明确日期时不自动设置截止日期；推测日期只能作为待确认提议。
- 被忽略项目保存纠错原因，不在相同证据上反复推荐。

每个正式待办、候选待办和建议都必须保存：

- 来源会话、应用、时间和活动分类。
- `SELF/P1` 参与关系。
- 证据原文和前后文。
- 归属理由。
- 声纹、语义和场景置信度快照。
- 创建、接受、修改、忽略和撤销历史。

## 11. 本地渐进个性化

- 用户修改活动分类时保存原分类、目标分类、规范化应用和匿名特征。
- 一次纠正只影响相似内容，不能形成“Chrome 永远是学习”之类的全局规则。
- 相似纠正重复出现后才提升个人规则权重。
- 准备形成长期规则时，Jarvis 必须展示规则并等待确认。
- 人物、声纹、场景、Todo 和建议反馈使用隔离的数据域。
- 一次忽略只降低相似建议权重，不永久屏蔽整个主题。
- 设置提供个性化规则的查看、停用、编辑、删除和全部重置。
- 学习记录只在本地保存，并纳入加密备份。

## 12. 主界面

### 12.1 三栏布局

- 左侧：Today、People、Topics、Todos、Memory、Storage/Settings。
- 中间：当前录音、波形、音源、实时转写；完成后显示本次会话。
- 右侧：固定的“今日行动”中心。

宽屏右栏建议从当前 320 px 调整到约 360–400 px。窄屏时右侧变为可展开抽屉，不能挤压录音和转写到不可用。

### 12.2 行动中心

从上到下固定为：

1. 现在要做：已到期、今天到期和置顶的正式待办。
2. 待你确认：别人分配且本人接受、日期/说话人需要确认的项目。
3. 候选建议：默认显示最多三条。
4. 稍后：未来日期或无日期的正式待办，默认折叠。
5. 今日已完成：默认折叠并允许撤销完成。

“查看全部”进入独立 Todo 页面进行搜索、筛选和历史管理。

### 12.3 卡片

默认卡片只显示：

- 标题和当前状态。
- 场景、规范化应用和时间。
- `SELF 明确承诺`、`对方分配且 SELF 接受` 等产生原因。
- 自动提取、待确认或候选建议标记。

展开证据后显示：

- 原文及前后两句。
- 说话人关系。
- 来源应用、场景和会话时间。
- 三类置信度。
- 音频播放或会话跳转。
- “说话人错误”“分类错误”“这不是待办”等纠错入口。

### 12.4 Finish 后的本次会话

点击 **Finish & Summarize** 后：

- 中间区域立即切换到本次会话，不弹出新窗口。
- 顶部逐项显示：音频已安全保存、最终转写处理中、说话人复核中、MiniMax 总结处理中。
- 已完成内容渐进出现，不等待全部后台工作。
- 提供三个标签：
  - 总结：主题、决定、人物、活动分类和重要信息。
  - 完整转写：按应用、说话人和时间组织。
  - 处理详情：转写覆盖、声纹状态、重试、资源让路和应用来源覆盖率。
- 右侧同步刷新待办、待确认和建议。
- 总结失败时保留转写和本地结果，并提供“付费重试”。
- 新录音开始后中间区回到录音状态；旧会话长期保存在 Memory。

## 13. 克制提醒

- 新提取内容只更新首页角标，不实时弹窗。
- 一次会话结束后最多一条合并通知。
- 只有已确认且设置提醒时间的正式待办能发送 Windows 通知。
- AI 推测日期确认前不能触发提醒。
- 候选建议永不发送系统弹窗。
- 全屏游戏、会议和演示期间延迟所有非紧急提醒。
- 退出受保护场景后合并提醒，不连续弹出。
- 支持专注模式和临时静音。

## 14. 数据和迁移

迁移必须保持旧数据、证据和任务可恢复，并继续遵守 SQLite 外键和幂等约束。

### 14.1 来源数据

重建 `audio_tracks` 的唯一性，使一个会话可以包含多条 system/application 轨，同时保留旧 `source_type` 兼容投影。新增：

- 稳定 `track_kind`：`mic`、`system_mix`、`application`。
- `application_key` 和本地展示名。
- `attribution_state`：`exact`、`mixed_unknown`。
- 应用活动/降级区间、捕获代次和覆盖率。

迁移旧 system 轨为 `system_mix`，旧 mic 轨为 `mic`。不能复制或丢失已有 chunk、segment、job、speaker turn 和 evidence foreign key。

### 14.2 活动分类

新增不可变分类输入、分类候选、采用结果和用户反馈。每次复核保存本地输入哈希、模型版本、预算尝试和匿名云载荷哈希。

### 14.3 行动候选

正式 `todos_v2` 和 `suggestions_v2` 继续作为长期结果。新增行动候选生命周期，用于待确认 Todo、候选建议、证据、置信度和决策历史。接受操作以事务方式创建正式 Todo 或更新 Suggestion，重复调用保持幂等。

### 14.4 个性化规则

反馈事件、候选规则、已确认规则和规则状态独立保存。规则不能覆盖证据或历史分类，只影响新的分类权重。

## 15. 隐私和安全门禁

- 进程路径和窗口标题只允许存在于原生发现组件的短生命周期内存中。
- 长期数据库只保存规范化应用键和用户可见名称。
- MiniMax 请求构建器使用字段白名单和递归敏感字段扫描。
- MiniMax 响应只能引用请求内允许的匿名说话人和证据 ID。
- 声纹 blob 使用现有本地加密能力；日志、IPC 公共投影和崩溃报告不得包含向量。
- 用户删除声纹或个性化规则后，后台缓存和派生索引也必须失效。
- 功能开关默认关闭新云分类，直到本地迁移、隐私测试和预算绑定全部通过。

## 16. 验收标准

### 16.1 应用来源

- KOOK 与 Chrome 同时播放时形成两个独立应用轨和一条混合安全轨。
- 应用关闭、重启和更换默认输出设备后能够恢复并记录缺口。
- 超过四个活动应用时按批准优先级降级，录音不断。
- 应用级采集失败时显示未知来源，不错误归属。
- 双轨/多轨回声不会在统一转写重复出现。
- 全屏 DOTA 2 时 Jarvis 不启动重型任务，退出后完整补齐。

### 16.2 说话人

- 三段录入均通过质量和一致性门禁。
- 中文 CAM++ 与 ERes2NetV2 使用独立版本和阈值。
- 本人自动归属、跨会话匿名人物自动关联在留出集达到至少 95% precision 后才可启用。
- 系统音频、重叠说话和未知来源不更新本人声纹。
- 用户可命名、撤销、拆分和合并人物。

### 16.3 分类和行动

- 80/55 阈值严格生效。
- 视频中的“你应该……”不会生成个人 Todo。
- 只有明确 `SELF` 承诺且三类置信度都达到 90% 才自动生成正式 Todo。
- 分配给他人的事项只保留在会议记录。
- 娱乐/游戏不生成建议或 Todo。
- 云端不可用或预算阻断时本地保守结果仍可用。

### 16.4 UI 和提醒

- 首页右侧按五个批准分区显示行动信息。
- 卡片来源、依据和证据可核查。
- Finish 后当前窗口渐进显示总结、完整转写和处理详情。
- 重启后会话、正式 Todo、候选状态、纠错和个性化规则保持一致。
- 全屏游戏期间无残留悬浮窗和非紧急通知。

### 16.5 回归和发布

- 旧数据库副本迁移前后行数、外键、证据引用和任务身份一致。
- 现有麦克风、系统混合录音、七天保留、FLAC、CUDA 让路和 MiniMax 预算测试保持通过。
- 测试、缓存、模型和打包产物继续写入 G 盘。
- 完整 Jarvis 测试、renderer 测试、typecheck、lint、构建和 Windows unpacked 启动通过。
- 真实 KOOK/Chrome/DOTA 2、实体麦克风、MiniMax 和双模型声纹 UAT 分别记录证据。
